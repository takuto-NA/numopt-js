# Adjoint L-BFGS の実装と比較

`adjointLbfgs` は縮約目的 f(p,x(p)) に L-BFGS を適用する。随伴方程式 c_x^T λ=f_x を解いた勾配 f_p−c_p^T λ を使う。状態復元と偏微分評価は他の Adjoint 法と共有し、two-loop recursion は無制約 `lbfgs` と共有する。

## 実装の判断

- 保持するのは最近 q 組の s=Δp、y=Δ∇f と 1/(s^T y)。既定 q=10、方向計算・履歴保存は O(qm)。m×m の逆ヘッセ行列は作らない。
- Strong Wolfe 探索は単位ステップから開始。試行点の状態を復元し、その点の真の随伴勾配を再計算する。共有探索が反復上限で未検証ステップを返す場合にも、受理前に Armijo 条件を確認する。
- 非降下方向は履歴をクリアして最急降下へ戻す。曲率 s^T y は有限・正、かつ ||s||||y|| に対する相対閾値を要求する。これはニュートンの対角ダンピングとは異なる。
- 受理済みの状態・勾配を次の反復へ再利用し、不要な求解を避ける。既存 BFGS はこの再利用を一部行わないため、比較は現在の公開実装全体の比較であり、two-loop のみの比較ではない。偏微分・目的・制約の評価数も生データに保存する。
- 勾配と制約の両方が許容誤差を満たして初めて `converged=true`。微小ステップは `stepStagnation`、探索失敗等は別の理由で終了する。`maxHistoryPairs` で保持した履歴数の上限を確認できる。
- 密な状態ヤコビアンの O(n²) メモリ・O(n³) 分解計算、制約の設計変数ヤコビアンの O(nm) メモリは残る。完全版 HVP も縮約ヘッセ行列は組み立てるため、Newton–Krylov ではない。

## 比較手順

```sh
npm run build
node scripts/scaling/lbfgs-comparison.mjs
node scripts/summarize-adjoint-lbfgs.mjs
# matplotlib が利用できる Python 環境で図を再生成する場合:
python scripts/plot-adjoint-lbfgs.py
```

同一環境・今回のビルドで BFGS、L-BFGS(q=10)、近似 Newton、完全 Newton（全結合ヘッセ行列／HVP）を再測定する。前回の時間値を流用しない。履歴比較は q=5/10/20。

独立した真の縮約勾配 RMS≤1e−6、既知解からの誤差 RMS≤1e−6、実際の制約残差 RMS≤1e−12 を共通終了基準とする。すべて解析一次微分・解析曲率。時間は専用プロセスで2回ウォームアップ後3回測定し、中央値と四分位範囲を保存する。ピーク RSS は別の新規プロセスを3回起動して OS の高水位を測る。Node、入力行列、JIT、GC 待ちの一時オブジェクトを含む全プロセスの値である。子プロセスは直列、V8 old heap は1024 MiB、子プロセス全体の上限240秒。

通常の `curved` は前回と同じ問題・初期値。`heterogeneous` は成分ごとの初期値を変える。追加した `ill-conditioned` は同じ縮約目的の各成分に1〜1000の対数間隔の重みを掛け、解での縮約ヘッセ行列の条件数を1000にする。状態ヤコビアンの条件は変えない。反復上限は通常100、条件数1000の問題は1000。

結果・生データは `benchmark-results/adjoint-lbfgs-{curved,heterogeneous,conditioned}.{json,md}` に保存する。このディレクトリは既存設定で Git 管理対象外。四分位範囲は記述的なばらつきであり信頼区間ではない。

交差点の追加測定 `adjoint-lbfgs-refined.json` は n=128、m=48/64/80/96/112/128、L-BFGSと完全版2経路について8回ウォームアップ後7回測定する。時間のみ測り、メモリ値は他の測定から補間しない。集計スクリプトは保存された全試行の独立精度基準を再監査する。

## 設計変数を増やした場合

Intel Core i9-14900K / Windows x64 / Node v24.22.1、測定コード `6d3be7a`。設計変数512・状態128、通常の `curved` の結果。各数値は中央値 [IQR]。

| 手法 | 反復 | 時間 ms | ピーク RSS MiB |
|---|---:|---:|---:|
| BFGS | 5 | 746.14 [15.96] | 106.18 [0.51] |
| L-BFGS（q=10） | 5 | 53.02 [0.82] | 78.89 [4.86] |
| 近似 Newton | 20 | 1903.89 [4.93] | 157.70 [12.09] |
| 完全 Newton（全結合） | 4 | 1033.84 [7.87] | 110.53 [0.73] |
| 完全 Newton（HVP） | 4 | 698.30 [6.21] | 98.58 [0.98] |

この点で L-BFGS は BFGS の約14.1倍、完全版全結合の約19.5倍速い。反復数はほぼ同じなので、設計変数が増えても密な逆ヘッセ行列を更新しない利点が出ている。

ただし BFGS の現実装は二つの密行列積を使う O(m³) 更新であり、一般的な O(m²) の rank-two 更新との比較ではない。設計変数128・状態128での目的関数評価は両方18回だが、一次偏微分コールバック評価は BFGS 101回、L-BFGS 76回、制約評価は53回と37回。この実装差も速度向上に含まれる。

## メモリの解釈

履歴だけの保存量上限は約 2qm 個の Float64 と q 個のスカラー。q=10、m=512なら約80 KiBであり、BFGS の単一の512×512行列の約2 MiBより小さい。ただし通常問題は5反復で終わるため、実際には履歴10組を使い切らない。条件数を上げた実験で q=5/10/20 を比較する。

全プロセスのピークは履歴以外に状態求解・行列コピー・GC 待ちの一時データを含む。たとえば m=256、n=512では、L-BFGSの約163.3 MiBより完全版HVPの約128.2 MiBが小さい。m=512、n=512でもL-BFGS約173.6 MiBに対して完全版HVP約158.2 MiB。L-BFGSが全プロセスのメモリでも常に最小になるとはいえない。

## 状態求解が支配的な場合

m=16、n=1024 の通常問題。時間・メモリは同じく3試行の中央値。

| 手法 | 反復 | 時間 ms | ピーク RSS MiB |
|---|---:|---:|---:|
| BFGS | 5 | 11475.01 | 301.3 |
| L-BFGS（q=10） | 5 | 8094.88 | 288.8 |
| 近似 Newton | 19 | 25941.99 | 309.9 |
| 完全 Newton（全結合） | 4 | 4361.00 | 201.6 |
| 完全 Newton（HVP） | 4 | 4321.86 | 191.2 |

この点では完全版HVPがL-BFGSより約1.87倍速い。設計変数は少なく、完全版の追加コストより状態・随伴求解を減らす効果が大きい。反対に m=512、n=512ではL-BFGSが1211.00 ms、完全版HVPが1869.26 ms、BFGSが2355.10 msであり、状態数が大きくても設計変数が増えると関係が変わる。

## L-BFGS を基準にした完全版との交差点

n=128、通常の `curved`、8回ウォームアップ後7回測定した時間中央値。前回の BFGS 基準の交差点とは異なる。

| m | L-BFGS ms | 完全版全結合 ms | 完全版HVP ms |
|---:|---:|---:|---:|
| 48 | 48.28 | 45.40 | 40.56 |
| 64 | 48.39 | 48.11 | 44.11 |
| 80 | 46.72 | 55.78 | 45.21 |
| 96 | 47.78 | 59.30 | 51.59 |
| 112 | 47.21 | 68.20 | 58.17 |
| 128 | 48.91 | 77.83 | 64.20 |

全結合版は m=48でL-BFGSより速く、m=64で四分位範囲が重なり、m=80で明確に遅い。HVP版はm=64で速く、m=80は僅差で範囲が重なり、m=96で明確に遅い。したがって分離できる境界はそれぞれ48〜80、64〜96の間であり、単一の整数の交差点までは断定しない。四分位範囲は記述的な比較であり、有意差検定ではない。

## 条件数と履歴数の影響

条件数1000、m=32、n=64。履歴を使い切る問題での比較であり、通常の5反復の結果から履歴数の良否を判断しない。

| 手法 | 反復 | 時間 ms | ピーク RSS MiB |
|---|---:|---:|---:|
| BFGS | 43 | 284.63 | 77.7 |
| L-BFGS q=5 | 269 | 487.96 | 94.2 |
| L-BFGS q=10 | 227 | 403.14 | 93.5 |
| L-BFGS q=20 | 188 | 344.77 | 85.3 |
| 近似 Newton | 20 | 51.95 | 65.0 |
| 完全 Newton（全結合） | 5 | 20.28 | 63.2 |
| 完全 Newton（HVP） | 5 | 20.16 | 63.7 |

履歴20は履歴10より約14.5%速いが、BFGSより約21%遅い。L-BFGSの低い1反復コストを、追加反復が上回る例となった。履歴数を増やせば任意の問題で改善するという意味ではない。

m=128、n=128では、L-BFGS q=5/10/20はそれぞれ281/271/256反復、1985.67/1961.08/1848.00 ms。一方、既存BFGSは通常設定で134反復に小ステップ判定の `converged=true` を返すが、独立した勾配 RMS は3.373×10⁻⁶で目標の10⁻⁶に未達だった。3試行とも同じ未達を記録し、その終了時間を目標達成までの時間として比較しない。独立した再現診断は `benchmark-results/adjoint-lbfgs-bfgs-diagnostic.json` に保存した。

ソルバ自身の終了許容誤差を1.13×10⁻⁷から1.13×10⁻¹¹に厳しくしたBFGS追試では、共通目標を満たす189反復まで続き、6288.84 ms、236.5 MiBだった。共通目標は変更しておらず、それ以上の精度まで走らせた時間でもない。`adjoint-lbfgs-conditioned-bfgs-refined.json` に通常設定と分離して保存する。

## 検証と適用範囲

集計で成功した時間363試行と、別プロセスのピークRSS237試行について、有限な勾配・解誤差・実制約残差と共通閾値を監査した。通常設定BFGSの未達3試行は別記し、ベンチマーク全体の終了コードは未達があることを示す1のまま保持する。`--resume` で成功済みの試行を再計算せず、後続の比較・追試を継続できる。

ソルバのテスト262件、型検査、ヘッダ検査、APIドキュメント生成、ESM/CommonJS/ブラウザの配布物検証が通った。two-loop は同じ初期スケーリングからの明示的な逆BFGS更新と照合し、非線形状態・残差目的・数値偏微分・短い履歴・非降下方向・不正曲率・探索失敗・停滞を検証する。

この結果は[前回の問題定義](adjoint-scaling.md)と同じ、密行列で表した良条件の結合状態系、分離可能な縮約目的を対象にする。疎なPDE、状態ヤコビアン自体の悪条件、任意の非凸目的関数には、今回の次元閾値をそのまま適用できない。大きな設計空間ではL-BFGSが有力だが、状態求解コストと実際の曲率・履歴数を含めて選ぶ必要がある。
